# SsalKit.DependencyInjection

Roslyn 소스 생성기 기반의 컴파일 타임 DI 자동 등록 라이브러리입니다. 리플렉션도, 어셈블리 스캔도, 런타임 비용도 없습니다.
[![NuGet](https://img.shields.io/nuget/v/SsalKit.DependencyInjection.svg?logo=nuget)](https://www.nuget.org/packages/SsalKit.DependencyInjection)

## 왜 SsalKit.DependencyInjection인가

DI를 "자동으로" 등록해준다는 라이브러리들은 대부분 애플리케이션이 시작될 때 리플렉션으로 로드된 어셈블리를 스캔하는 방식을 사용합니다. 이 방식에는 실질적인 비용이 따릅니다. 어셈블리 수가 늘어날수록 시작 시간이 길어지고, 트리밍이나 Native AOT가 분석할 수 없는 메타데이터가 생기며, 문제가 있어도 런타임에야 비로소 드러납니다.

SsalKit.DependencyInjection은 접근 방식 자체가 다릅니다.

- **런타임이 아니라 컴파일 타임에 처리합니다.** 소스 생성기가 빌드 과정에서 코드를 분석해 등록 코드를 C#으로 직접 생성하므로, 앱이 시작될 때 스캔 단계를 거칠 필요가 없습니다.
- **리플렉션을 전혀 사용하지 않습니다.** 생성되는 코드는 평범하고 읽기 쉬운 `IServiceCollection` 확장 메서드일 뿐입니다. 동적으로 탐색되는 것은 아무것도 없습니다.
- **AOT/트리밍에 친화적입니다.** 등록 코드가 리플렉션 기반 탐색이 아닌 일반적인 생성 코드이기 때문에, 추가 어노테이션 없이도 트리밍과 Native AOT 컴파일을 그대로 통과합니다.
- **컴파일 타임 진단을 제공합니다.** abstract 클래스를 등록하거나 구현하지 않은 인터페이스를 지정하는 등의 실수를 프로덕션 런타임 예외가 아니라 컴파일러가 먼저 잡아줍니다.

## 설치

```bash
dotnet add package SsalKit.DependencyInjection
```

이 패키지 하나에 `[Service]` attribute와 소스 생성기가 모두 포함되어 있어, 별도의 analyzer 패키지를 추가로 설치할 필요가 없습니다.

## 빠른 시작

등록하고 싶은 클래스에 attribute를 붙이면 됩니다.

```csharp
using Microsoft.Extensions.DependencyInjection;
using SsalKit.DependencyInjection;

// 구현한 인터페이스 전부로 등록됩니다 (구현한 인터페이스가 없으면 자기 자신으로 등록).
[Service(ServiceLifetime.Singleton)]
public class CacheService : ICacheService { }

// 지정한 타입 하나로만 등록됩니다.
[Service(ServiceLifetime.Scoped, As = typeof(IUserRepository))]
public class UserRepository : IUserRepository, IDisposable { }

// 기본값은 ServiceLifetime.Singleton입니다.
[Service]
public class EmailSender { }

// Keyed 서비스로 등록됩니다 (.NET 8+ keyed DI).
[Service(ServiceLifetime.Singleton, Key = "redis")]
public class RedisCache : ICache { }

// IClock이 아직 등록되지 않은 경우에만 등록됩니다.
[Service(ServiceLifetime.Singleton, Mode = RegistrationMode.TryAdd)]
public class DefaultClock : IClock { }
```

빌드 시 생성기는 어셈블리별로 그 이름을 딴 확장 메서드를 하나씩 생성합니다. 예를 들어 `MyApp.Web`이라는 어셈블리에서는 `AddMyAppWebServices()`가 생성되며, 대략 다음과 같은 코드입니다.

```csharp
// <auto-generated/>
namespace Microsoft.Extensions.DependencyInjection;

public static class MyAppWebServiceCollectionExtensions
{
    public static IServiceCollection AddMyAppWebServices(this IServiceCollection services)
    {
        services.AddSingleton<CacheService>();
        services.AddSingleton<ICacheService>(sp => sp.GetRequiredService<CacheService>());

        services.AddScoped<IUserRepository, UserRepository>();

        services.AddSingleton<EmailSender>();

        services.AddKeyedSingleton<ICache, RedisCache>("redis");

        services.TryAddSingleton<IClock, DefaultClock>();

        return services;
    }
}
```

`Program.cs`에서는 다음과 같이 호출하면 됩니다.

```csharp
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddMyAppWebServices();

var app = builder.Build();
```

> 여러 인터페이스를 구현하는 `Singleton`/`Scoped` 서비스는 concrete 타입 등록과 팩토리 포워딩으로 생성되므로, 어떤 인터페이스로 조회하든 항상 같은 인스턴스를 공유합니다.

## Attribute 레퍼런스

`[Service(lifetime, As = ..., Mode = ..., Key = ...)]`

| 속성        | 타입                | 기본값                       | 설명                                                                                   |
|------------|---------------------|------------------------------|----------------------------------------------------------------------------------------|
| `Lifetime` | `ServiceLifetime`    | `ServiceLifetime.Singleton`  | 생성자 인자입니다. `Singleton`, `Scoped`, `Transient` 중 하나입니다.                        |
| `As`       | `Type?`              | `null`                       | 구현한 모든 인터페이스(또는 자기 자신) 대신 지정한 타입 하나로만 등록합니다.                     |
| `Mode`     | `RegistrationMode`   | `RegistrationMode.Add`       | `Add`, `TryAdd`, `TryAddEnumerable`, `Replace` 중 하나로, 컬렉션에 등록을 적용하는 방식입니다.  |
| `Key`      | `object?`            | `null`                       | 지정하면 `Add*` 대신 `AddKeyed*`를 사용해 keyed 서비스로 등록합니다 (.NET 8+).                |

한 클래스에 `[Service]`를 여러 번 붙여서 서로 다른 lifetime, `As` 대상, key로 한 번에 여러 방식으로 등록할 수도 있습니다.

## 진단(Diagnostics)

소스 생성기는 컴파일 타임에 `[Service]` 사용을 검증합니다.

| ID        | 심각도    | 설명                                                                          |
|-----------|-----------|-------------------------------------------------------------------------------|
| `SSAL001` | Error     | `[Service]`가 abstract 또는 static 클래스에 적용되었습니다.                        |
| `SSAL002` | Error     | `As`에 지정한 타입을 해당 클래스가 구현하고 있지 않습니다.                            |
| `SSAL003` | Error     | Open generic 타입은 지원하지 않습니다.                                            |
| `SSAL004` | Warning   | 동일한 서비스 등록이 중복된 것으로 보입니다.                                        |
| `SSAL005` | Error     | `Key`와 `RegistrationMode.TryAddEnumerable`은 함께 사용할 수 없는 조합입니다.       |
